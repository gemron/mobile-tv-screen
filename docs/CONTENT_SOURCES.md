# 电脑独立点播与直播

MobileTV 的影视与直播入口直接由电脑请求订阅、影片接口和媒体资源。手机可以关掉，不需要手机上的 OK影视、Android 运行环境、Java 或模拟器。投屏功能仍可独立使用。

## 当前兼容情况

| 来源 | 支持内容 | 边界 |
| --- | --- | --- |
| TVBox JSON / JSONC 订阅 | 站点、解析器、直播列表、配置仓 | 支持注释、尾逗号、Base64 及带 `**` 标记的图片封装 |
| type 0 | XML 采集接口 | 分类、分页、搜索、详情、剧集 |
| type 1 | JSON 采集接口 | 同上，保留接口已有查询参数 |
| type 4 | CatVod HTTP API | 分类、分页、搜索、详情、play 解析 |
| `csp_T4` / `csp_T4Guard` | FTY 扩展配置解码后访问采集接口 | 实现配置编码格式，不加载原插件 |
| `csp_Dm84` / `csp_Dm84Guard` | 动漫巴士分类、搜索、剧集、播放器接口 | 支持 iframe 与公开解析接口，未执行网页脚本 |
| `csp_Auete` / `csp_AueteGuard` | 奥特分类、搜索、剧集、媒体地址 | 支持播放器 URL 和 Base64 地址 |
| `csp_FirstAid` / `csp_FirstAidGuard` | 急救分类、搜索、教学视频 | 使用站点公开 HTML 和视频地址 |
| M3U / TXT / JSON | 频道分组、搜索、多线路、换台 | 支持 VLC UA / Referer、URL 后的请求头参数 |
| 其他私有接口的原生移植 | B站、加密 App、站点 HTML、网盘、体育等 | 接入和实际验证情况见逐项清单；未移植接口仍显示原因，不直接运行 JAR / DEX / ARM 库 |
| drpy / JavaScript | 虎牙、斗鱼、兔小贝的数据声明与独立站点处理器 | 其他脚本需专用移植，不在 Node 主进程执行第三方代码 |

1.1.0 初始支持 49 条目中的 5 个站点。1.2.0 预览接入更多原生处理器，并提供网盘、站点验证与磁力入口。接入数不能代表实播成功数，当前结果以[逐项兼容清单](SOURCE_COMPATIBILITY.md)为准。真实 Edge 初始抽测：光影、奶酪、奥特、动漫巴士为 1920×1080，急救为 1280×720；本轮文采、瓜子与 B站抽测也已出画面。画质不代表站内所有影片。

该配置中的「综合」读取到 112 个频道、6 个分组；Kimentanm 读取到 120 个频道、4 个分组。列表成功不等于每个频道当前都能播放。指向 Android 本机 `127.0.0.1:9978/proxy` 的直播源会明确标为待适配，电脑不能直接复用手机本地服务。

同次验证还读取了虎牙、斗鱼、YY 频道列表，并通过真实 Edge 播放 Kimentanm 中的 CGTN 英语直播。频道数量和节目可用性会随源站实时变化。

## 使用方式

在顶部选择「影视」或「直播」，点击「片源管理」添加自己的订阅 URL，也可给地址命名。最多保存 30 个地址，主界面的订阅下拉框可直接切换；更新同一地址不会生成重复项，读取失败保留原配置。切换使用上次成功读取的配置，需要更新时在管理中重新载入地址。程序未内置、推荐或捆绑第三方内容源。订阅可使用中文域名，保存时按标准 URL 转成可请求的域名。

「播放历史」保留最近 200 个影片／频道记录，自动记录最新剧集和进度；「收藏」支持影片及直播频道，最多 500 项。记录与订阅绑定，避免不同订阅的站点或影片编号冲突。点击历史继续观看，接近片尾的影片从头播放；收藏影片打开线路／选集，收藏频道直接播放。恢复时重新解析媒体地址，不将临时视频链接作为历史存储。移除订阅后对应记录仍保留，重新添加同一地址后可恢复；历史可逐条删除或清空，收藏可取消，数据均保存在本机的 `library-collection.json`。

点播：选择站点 → 分类 / 搜索 → 详情 → 线路 → 剧集。支持 type 0 网页和 type 1 JSON 解析接口，部分站点使用独立浏览器解析；2/3 扩展与 4 聚合解析尚未实现。先执行站点播放解析，再调用选择的解析器。多画质返回值在播放中可选择并恢复进度，播放器显示实际视频尺寸。

选集弹窗立即显示加载动画；选择剧集后显示解析动画、剧集名称、等待秒数与「取消」。换集只接受最新请求的结果，旧请求的错误或成功不会覆盖当前选择。关闭弹窗或换线路取消等待；服务端解析默认最多 40 秒，界面最多等待 45 秒，超时后提供「重试本集」。取消已发出的网盘保存不能撤销远端已经接受的保存任务。

厂长等 Artplayer 页面可静态读取播放器配置和变量赋值，识别无扩展名 MP4；忽略广告插件及封面地址，不执行网页脚本。2026-11-16 对所反馈的厂长第 2 集实测得到 1920×800、约 68 分钟正片，并验证播放与拖动；这不代表所有播放器结构或站点广告形式均已支持。

豆豆片单包含推荐、热播、电影/电视筛选与榜单。点击片单直接跨源搜索；也可在搜索栏勾选“全部片源”。结果逐步出现，可先选择已有结果，或点击“停止”。跨源搜索遵循订阅的 `searchable` 开关，支持公开网盘搜索，排除“我的网盘”私人文件目录。切站和取消搜索会停止后台请求。

单站和跨源搜索优先显示完整片名一致、包含完整搜索词的结果，再比较拆分词及演员资料。可直接输入演员名，也可组合片名和演员，例如“狂飙 张译”。演员命中会在卡片上标明姓名；演员匹配依赖片源返回的演员字段。后返回的精确结果会提升位置，当前卡片的键盘焦点保留；结果较多时保留相关度较高的前 300 项。

网盘线路按实际平台标注；需要登录或提取码的线路会保留验证提示，点击“打开登录 / 验证页面”，完成后“重新读取线路”。浏览器状态可在“网盘账号”中验证并保存，账号状态变化会清除对应网盘元数据缓存。网盘返回的多档媒体可手动选择；分享接口失效时尝试独立官方浏览器解析，未登录、无权限或需要验证码时仍可能无法播放。手机上的私有代理不能直接作为电脑独立实现已完成的证据。

部分夸克视频要求先保存到自己的网盘，登录本身不能解除这个要求。遇到官方明确提示时，界面会显示所选文件名、空间占用和“保存这一集并播放”按钮。点击后只将这一集保存到夸克网盘根目录，不会自动保存整部或下一集，也不会自动删除网盘文件。保存后尝试读取账号可用画质；仍受网盘空间、文件权限、会员及格式限制。已完成文件和未完成任务的本机引用保存在 `cloud-shares.json`，重试复用已有任务，播放失败不会自动重复转存。保存请求成功提交不等于保存完成；以远端任务完成和实际播放器出画面为准。

豆瓣海报经接收端图片代理携带对应来源信息读取，避免图片防盗链导致空白；无法读取的图片显示明确占位。

直播：选择源 → 分组 / 搜索 → 频道，可按名称或编号找台，点击 ☆ 收藏频道。可筛选收藏频道、继续上次观看。播放中的「频道表」或 `C` 打开侧边列表，`↑` / `↓` 选择、Enter 换台、Esc 收起；输入频道编号后 Enter 或稍候自动选台。`N`／`P` 和 PageDown／PageUp 换台，「换线」用于有多个地址的频道。上下台按当前源完整频道表循环；直播隐藏点播进度条，其他播放器快捷键保持有效。

进度条浅色区间表示播放器已缓冲、可播放的区间，绿色表示已播放位置；拖动后可能保留多段缓冲，兼容封装的区间按整部影片时间显示。服务端原文件缓存量在设置中另行显示，不把文件字节数假定成精确的时间缓冲。设置面板点击外部收起，设置弹窗点击背景关闭；站点要求验证时，错误旁显示「打开验证页面」和「重试」。

配置保存在运行数据目录的 `library-config.json`。Windows 安装版默认是 `%LOCALAPPDATA%\MobileTV\data`。该文件可能含订阅令牌或请求头，不应上传到公开仓库。界面的兼容摘要不会返回 Cookie、Authorization 或原始插件扩展配置。

## 运行方式与缓存

- 订阅读取最大 8 MiB，超时和重定向均有上限；HTML 页面最大 4 MiB。
- 分类、搜索、详情与频道元数据缓存合计最多 16 MiB、32 项，按用途过期。
- 需要专用请求头的媒体使用服务端上下文 ID，媒体代理、HLS 子清单、分片和密钥均沿用同一上下文。
- 夸克官方 HTTPS 视频和原文件域名需要会话 Cookie，清单、同域分片及原文件读取保留该凭据；不同画质分别校验目标域名，不会把网盘会话发送给外部 CDN、相似域名或跨域跳转。
- 夸克自己的网盘文件及已授权保存的分享默认选择“原文件（原画）”，保留标注为“预览”的可用转码档位；原文件地址不可用时仍可使用可用预览。每次重新播放或切换画质重新获取临时地址，不自动保存其他文件。
- 原文件使用 HTTP Range 按需播放；夸克原文件按 96 KiB 分块，初始最多 96 路并行；2K／4K 最多 192／384 路，按需使用最多四条 HTTP/2 连接。初始缓存 32 MiB、前向预读约 22.5 MiB；按实际解码分辨率，720p／1080p／2K／4K 上限分别为 64／128／256／512 MiB，前向预读目标约 90／120／150／180 秒。使用文件总大小和时长估算码率并保留波动余量，前向字节窗口最多 384 MiB，时间目标受容量上限约束，不预先分配全部内存。清晰度变更重新计算，旧会话分辨率不能覆盖新会话；停止播放释放缓存。多个上游小分段顺序拼接为同一个播放器响应，未下载完整的分块也能即时供播放。官方原文件地址优先 HTTP/2 复用连接，约 900 次请求后提前轮换并保留已有读取；GOAWAY 或未处理的流可有限重试，不支持时回退 HTTP/1。凭据按流携带，跨域跳转沿用既有隔离规则。原生播放起播目标约 10 秒，兼容封装约 2 秒；读取到元数据后最多额外等待 12 秒，已有解码画面但没有缓冲区间时直接起播。拖动优先，停止或换片取消旧预读，不完整响应不入缓存，已收齐但尚在结束的响应不被误取消；已取消的客户端不能改变新位置的预读窗口。缓存不落盘，视频不重编码，真实样本已验证 1920×1080 出画面和跳转 02:13 后继续播放。不同授权接口可能返回不同下载线路；不直接替换已签名地址的域名。实际流畅度仍受源站速度、码率及设备解码能力影响。
- MKV 自动经现有受保护的代理读取并转为 MP4 封装，沿用原文件并行缓存及凭据隔离；视频码流复制、音频转换为 AAC，保留总时长及续播位置。真实 Edge 已验证 3840×1608 HEVC MKV 出画面并连续播放。HEVC 仍需浏览器和硬件解码支持；无法解码时明确提示，避免音频独自播放。
- 转封装在初始媒体包到达后写入 MP4 时间轴编辑信息，保留拖动后的音视频相对时间，避免视频保留关键帧预解码、音频精确裁剪时被分别重置起点而产生声音提前。闪光／提示音回归覆盖合流与分离 DASH，继续直接复制视频码流。
- 账号管理也支持 B站官方网页登录。我的网盘目录仅列网盘平台，不把 B站账号当作网盘目录。B站专用投屏见[说明](BILIBILI_CAST.md)。
- 上下文最多 256 项，空闲 6 小时后失效；缓存按上下文隔离，避免不同请求头串用。
- HLS 点播沿用原播放器的 60–90 秒缓冲与 64 MiB 分片缓存；不将所有直播分片永久写入磁盘。
- 常规 HLS / MP4 不重编码。需要 FFmpeg 时默认视频码流复制；源站给多少清晰度就播放多少，不会把低清伪装成高清。
- 新的播放请求、配置切换和手机投屏会使旧解析失效，迟到的解析结果不能覆盖新会话。

## 添加适配器

通用接口与媒体解析在 `src/content/catalog.js`，原创 HTML 适配器在 `src/content/html-sites.js`。`describe()` 识别插件名称，`list()`、`detail()`、`resolve()` 分别实现列表、剧集和媒体解析。新增适配需要提供本地可重复的协议测试，确认分类、搜索、分页、详情、线路及实际媒体播放；仅成功解密扩展配置不能算完成站点适配。

当前实现只重现互操作所需的配置格式、请求参数和页面数据结构。仓库与发行包不分发第三方私有插件、还原后的 DEX 或反编译源码，不把整个 Android 业务执行环境搬进 Node.js。

更多原生实现位于 `src/content/adapters/`，统一通过 `providers.js` 路由。部分加密接口按需读取用户订阅声明的插件容器的数据常量，ZIP/DEX 大小、目录、数组和校验均受限制，只在内存处理。网盘账号在 `cloud-accounts.json`，保存文件引用在 `cloud-shares.json`，站点覆盖值在 `library-overrides.json`，匿名设备身份在 `source-runtime.json`；这些文件不得提交仓库。

磁力入口使用 WebTorrent，仅在用户打开磁力详情后取得元数据，选中媒体文件才下载；一次保留一个播放任务，单文件与临时缓存上限 2 GiB。停止或切换播放会清理临时任务；P2P 速度取决于做种者。当前使用 TCP，缺少可选 uTP 原生组件不会阻止 TCP 播放。

广告过滤见[详细说明](AD_FILTER.md)。

## 本地验证

```powershell
npm test
npm run test:library:browser
```

浏览器测试创建临时数据目录和独立 Edge 配置，使用本地合成媒体验证播放、专用 UA / Referer、自动连播与换台。不会修改日常使用的订阅。

需要对用户给定的第三方源作实时验证时，可显式联网运行：

```powershell
npm run test:library:browser -- --real-source
# 只验证其中一个站点
npm run test:library:browser -- --real-source --site=Dm84
# 使用同一订阅中的 CGTN 英语频道验证真实直播
npm run test:library:browser -- --real-live
```

这项可选测试不进入默认 CI，因为源站可用性、域名变化和接口风控不由本项目控制。实际测试分辨率和前进时间会打印到终端。
