# B站专用投屏

在 **设备设置 → B站专用投屏（实验）** 开启，手机投屏列表选择 **我的小电视**。新安装默认关闭；普通 MobileTV DLNA 设备继续独立存在。这是 MobileTV 的兼容接收实现。

## 已接入功能

| 功能 | 行为与验证 |
| --- | --- |
| 设备发现与连接恢复 | SSDP 独立描述、HTTP/NVA 握手、分包/合包、心跳和会话恢复；B站 Android 9.19.0 已识别为专用投屏设备 |
| 播放控制 | 播放、暂停、停止、拖动、音量、倍速；旧手机会话不能操作后来切换的其他来源 |
| 画质切换 | 回传平台提供的画质列表及实际选中的 QN，切换保留进度和暂停状态；真机选择 1080P/720P，桌面分别实测 1920×1080/1280×720 |
| DASH 音视频 | FFmpeg 合并分离音视频，默认复制视频码流；保留源视频总时长，拖动时从对应时间重新取流 |
| 弹幕 | XML 历史弹幕按进度显示、滚动/顶部/底部样式、开关同步、暂停及拖动同步；手机发来的即时弹幕仅在本机显示，不代用户发布到 B站 |
| 分集连播 | 按视频分P列表自动播放下一项，向手机回传结束和选集状态；迟到的结束上报不会跳过下一项 |
| B站账号 | 官方网页扫码登录、保存和验证本机浏览器登录状态、退出当前平台账号；用户完成扫码后的真实登录检查已通过 |
| 番剧、课程、直播接口 | 已加入对应的网页播放接口和协议测试；是否能播放取决于平台响应、当前账号权限和格式，不能把接口单测当作全部内容的真机验收 |

弹幕、连播及播放控制还有实际 Edge 回归测试。画质菜单中出现 HDR/4K 不等于已取得对应媒体：测试账号请求 4K（QN 120）时，平台仍返回 1080P（QN 80）。未取得所选档位时保留当前播放并提示，避免反复重开视频或标注虚假分辨率。

## 登录和支持边界

从 **设备设置 → B站账号** 或影视页的 **账号管理** 选择 B站，打开官方登录页扫码，完成后点击“保存浏览器登录状态”。只有官方会话检查通过才显示已登录；失败的同步不会覆盖原有有效账号。

登录状态只保存在运行数据目录的 `cloud-accounts.json`。该文件及独立浏览器配置不得打包或提交仓库。手机随投屏发来的访问令牌仅用于本次内存会话，不写入配置、不输出日志。

目前不实现官方 TV 客户端的 `LoginWithCode` 一键授权流程，使用官方网页扫码登录替代；没有打包官方应用签名密钥或 Android SDK。DRM 授权播放尚不支持。高清、HDR、4K、番剧和课程还受到平台权限、格式及设备解码能力限制。

## 端口与测试

默认 TCP `9958`，发现使用已有 UDP `1900`。开关保存在 `bilibili-cast.json`；也支持 `ENABLE_BILIBILI_CAST=1`、`BILIBILI_CAST_PORT` 及服务器测试参数。设备发现由已有 SSDP 服务发送。端口启动失败会在设置中显示错误。

```powershell
node tests/bilibili-media.js
node tests/bilibili-cast.js
npm run test:library:browser
```

协议字段和消息结构参考作者的一手资料：[NVA 协议分析](https://www.xfangfang.cn/028)、[Macast Nirvana 插件](https://github.com/xfangfang/Macast-plugins/tree/main/nirvana)。Node.js 实现独立编写，未分发其 Python 插件。平台更新后仍需重新核对客户端版本和真实行为。
